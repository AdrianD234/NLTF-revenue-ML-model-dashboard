# Implementation report — PED activity publication through FY2050

Branch `fix/revenue-outlook-ped-activity-through-2050`, from
`31b74615d9d91bb001516282fd3a1177292f1e08` (PR #20).

**Status: Phase 1 partially complete. Not ready for Phase 2 and not ready to
merge.** The two governed constructions are built and proven; the app-side
wiring that makes them visible is not written. Details below are exact about
which is which.

## What is done and verified

### 1. Corrected diagnosis (section 5) — complete

`publication_break_diagnosis.md` and `publication_layer_coverage.csv`,
generated by `scripts/diagnose_ped_activity_publication.py` over both engines.

The brief's premise needed two corrections:

- **`ped_vkt_per_capita` annual was never broken.** It already publishes
  FY2025→FY2050 stamped `post_model_extrapolation`. Annual sections 6-7 and
  blocking tests 1-18 were already satisfied for it on merged main. Its only
  defect is quarterly.
- **`light_petrol_vkt` does not fail at `post_model_chart_rows`.** It is absent
  from `DISPLAY_SERIES_ORDER` and the 14-row series-trace contract, so every
  runtime chart-row builder drops it and it has zero rows at the persisted
  layer. `post_model_chart_rows` is the last layer to drop it, not the cause.

Four layers were being conflated; the CSV separates them.

### 2. Additive annual publication (sections 6-7) — implemented and verified

`_append_post_model_ped_activity_chart_rows` in `revenue_outlook.py`, called
from the bridge pass immediately after `_append_selected_light_petrol_vkt_rows`
and before the scenario overlays. Named contract
`POST_MODEL_PED_ACTIVITY_CHART_SERIES`, a closed tuple — not a
publish-every-hidden-leaf rule.

Verified against the promoted pack: 40 rows added; chart value equals the
post-model line-reconciliation value at **max abs diff 0.0** for both
scenarios; `ped_vkt_per_capita` unchanged at 26 rows; **no row created at or
below FY2030**, so the rendered econometric window cannot move.

`DISPLAY_SERIES_ORDER` and the series-trace contract are untouched, per the
owner decision.

One defect found and fixed during implementation: the comparison scenario is
labelled `Current finalist High population/comparison` in line reconciliation
but `Current finalist comparison behavioural path` in chart rows. Joining on
`source_path`/`trace_name` publishes the Base case alone and silently drops the
comparison. The join is on `scenario_name`.

### 3. Joint quarterly construction (sections 12-13) — implemented and verified

`post_model_ped_activity_quarterly_rows` in
`revenue_outlook_series_coverage.py`, with
`METHOD_POST_MODEL_RAW_SHAPE` and `POST_MODEL_PED_ACTIVITY_QUARTERLY_SERIES`.

Section 12 asked whether one common scale factor satisfies both annual
constraints or whether a constrained correction is needed. **It closes in
closed form**, for a structural reason: the annual constructor derives
`scenario_population` as exactly `petrol_fy / vktpc_fy` off the same raw path
(`post_model_extrapolation.py:290-297`), so `target_vktpc = scale_fy *
vktpc_fy` follows algebraically.

Measured over both engines, both scenarios, FY2031-FY2050 — 80 fiscal years,
320 quarters, counts asserted so the audit cannot pass vacuously:

| check | worst relative residual |
|---|---|
| annual VKT-per-capita sum | 3.4e-16 |
| annual petrol sum | 3.3e-16 |
| per-quarter petrol/VKTpc/population identity | 4.0e-16 |
| negative quarters | none |

That is 1-2 ULP. **No KKT system, no reconditioning, no constrained correction.**
The section 12 fallback is implemented as a fail-closed guard, not an expected
code path.

End-to-end through the builder: 320 rows, exactly 2 series x 2 scenarios x 20
years x 4 quarters, spanning **2030Q3-2050Q2** with no 2050Q3/2050Q4 row.

Evidence: `annual_ped_identity_audit.csv`, `quarterly_ped_identity_audit.csv`.

## What is NOT done

Listed explicitly rather than left to inference.

1. **App-side wiring — the blocking gap.** `_filter_series_rows_with_fallback`
   tests for missing quarters **per trace**: a trace with any native quarters
   never enters `missing_traces`, so the derivation is never invoked for
   FY2031-FY2050 at all (the diagnostic records
   `L4_quarterly_used_fallback = False` for `ped_vkt_per_capita`). This must
   become a per-period gap fill, and the builder needs the raw quarterly audit
   and scenario population threaded through from the pack. That touches several
   call sites and the cache identity (sections 18-19), so it was not started
   rather than left half-applied.

   **Until this is done, neither quarterly path renders to 2050Q2 and the
   annual `light_petrol_vkt` fix is unproven end-to-end in the running app.**

2. **Blocking tests (sections 20-21).** None of the 38 written. Two existing
   tests will fail by design once wiring lands and must be updated:
   `test_light_petrol_vkt_current_rows_really_do_stop_at_fy2030` (its docstring
   anticipates exactly this change) and
   `test_a_short_current_path_is_declared_not_extrapolated`. Section 16 requires
   the coverage note to fall silent because plotted coverage is complete, not by
   hardcoding.

3. **Remaining audits (sections 14-18):** conflict quarter audit, official
   vintage audit, policy-state and band coverage, cache invalidation,
   seam audit, before/after coverage matrices.

4. **Pack rebuilds (section 24).** Not started. The replay cache is **already
   fail-closed stale** from the source edits — correct behaviour, and it means
   the diagnostic script cannot re-run until the rebuild. Order must be replay
   cache, then quarterly display pack, then policy runtime last.

5. **Browser acceptance (section 22), performance (19), full suite, extract
   validation, deployment readiness, replay parity, CI.** None started.

## No section 27 stop condition was hit

The governed FY2031-FY2050 source rows exist for both series; both identities
close to machine precision; FY2026-FY2030 values are untouched by construction;
no official value moved; no unapproved assumption was needed. Work stopped on
context budget, not on a governed blocker.
